## Compact Rules (auto-injected by orchestrator)

### Astro 5 / TypeScript (project stack)

When touching `src/**/*.astro`, `src/**/*.ts`:

- **Components**: `.astro` components — server logic in the frontmatter fence (`---`), markup below. Keep client JS minimal; put browser behavior in `src/scripts/*.ts` and import from a `<script>` (see `scroll-reveal.ts`, `contact-form.ts`).
- **Bilingual i18n (CRITICAL)**: UI strings live in `src/i18n/es.ts` + `src/i18n/en.ts`. NEVER add a key to one locale without the other — parity is enforced by `npm run check:parity` (`scripts/check-bilingual-parity.ts`) and `tests/unit/bilingual-parity.test.ts`. `es` is the default locale.
- **Routing**: file-based in `src/pages/`. Default (`es`) routes at root; English mirror under `src/pages/en/`. Dynamic project pages: `projects/[slug].astro` + `en/projects/[slug].astro` — keep both in sync.
- **Content collections**: defined in `src/content.config.ts` with zod schemas in `src/content/schemas.ts`. Add/modify content via the collection schema, don't hardcode.
- **Path alias**: import from `@/*` (→ `src/*`), not long relative paths.
- **Types**: `astro/tsconfigs/strict`. No implicit `any`. Type check with `astro check` (also runs in `npm run build`).
- **Style**: single quotes, 2-space indent (editorconfig + Prettier). Format with `prettier --write .` (uses `prettier-plugin-astro`).
- **Output**: `output: 'static'` — no SSR adapter. Deploys to Firebase Hosting (`npm run deploy`).
